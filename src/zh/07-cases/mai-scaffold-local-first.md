## 现场

### 1. 背景

立项写开源书《让 Grok Bot 成为你的 AI 队友》，仓库定在 `yangwenmai/grok-bot-ai-teammate`。目标是本机能 `mdbook serve` 试读；删文件须 Mai 确认。

### 2. 派活

- 结构站：mdBook 空壳 + 中英目录 + Pages CI；不写长章；不删已有 `LICENSE` / `README`
- 编辑 / 共创 / 案例：目录导语、CONTRIBUTING、案例模板先交可挂进壳的草稿
- 约束后来补了一条（见过程）：未点头前不 commit、不 push

### 3. 过程

1. 建仓一度 **blocked**：本机 `gh` 当时只有 `maiyang-as`，目标账号是 `yangwenmai`。房内改交本地脚手架，不假装仓已通。
2. 仓通后结构站先试 Cloud Agent 落壳，**额度不够**，改走本机仓开分支。
3. 开出 [PR #1](https://github.com/yangwenmai/grok-bot-ai-teammate/pull/1)（壳、模板、CONTRIBUTING、CI）。
4. Mai 拍板：初期自己搭骨架，**不必开 PR**；#1 关闭。内容改非工作时段直接合 main——随后又改口。
5. Mai 再改：先只输出到本地，**不要 commit / push**；合 main 暂停。全席对齐：稿件落本机 / handoffs，推仓等点头。

### 4. 结果

- **半成**：本机九段目录可翻，`mdbook build` 绿；试读命令可用。
- **远程**：骨架 PR 未合；最新试读正文按指令留在本机工作区，未推。
- 案例模板路径随目录改版从 `04-field` 迁到 `07-cases`（本机已改链，未推仓）。

### 5. 复盘

- **有效**：账号不对、额度不够时先标 `blocked` 并交本地替代物，比空等有用。
- **翻车根因**：把「开源协作默认走 PR」套进 **主人还在定骨架** 的阶段；推仓策略变了两次，中间产物（PR）作废成本高。
- **下次派活改哪句**：开写前写死——「本阶段：只写本机 / 可开 PR / 可直推 main」三选一；默认值不要假设。
