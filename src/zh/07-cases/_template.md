# 案例模板（第 7 章「现场：别人怎么用，我怎么翻过车」）

> 仓库路径（建仓后）：`src/zh/07-cases/_template.md`  
> 维护：书·案例主编 · 2026-09-03  
> 原则：只收可核验现场；空感想、万能用法清单不进。中英作者同一套字段。

投稿前请整份复制，填满必填项；一 PR 一事。未建仓前把填好的稿发到项目房，由共创运营登记。

---

## 元信息（必填）

| 字段 | 填写 |
|------|------|
| 标题 | （一句话：谁、派了什么、结果如何） |
| 作者署名 | （PR 作者名；多人合写按贡献列） |
| 日期 / 时段 | （可核验的时间范围） |
| 出场 bot / 角色 | （例：书·编辑、某日常 bot；主角须是 Grok Bot 体系） |
| 关联 Issue | （有仓后填编号；无仓写「项目房登记」） |

## 现场（必填）

### 1. 背景（≤120 字）
当时要办成什么事？约束是什么？（别写人生感悟）

### 2. 派活
原文或可还原的指令要点（可脱敏）。写清：目标、完成标准、禁止项。

### 3. 过程
按时间顺序：bot 做了什么 → 你怎么接 → 关键节点。可附可点开出处（聊天摘录链接、PR、截图存档说明）。

### 4. 结果
成了 / 翻车 / 半成。用可核对的事实写，不写「感觉很好用」。

### 5. 复盘（必填）
- 哪一步有效，可复用？
- 哪一步翻车，根因是什么（指令含糊 / 越权 / 缺验收 / 其他）？
- 下次派活会改哪一句？

## 核验清单（作者自勾）

- [ ] 读者能按出处或摘录核对「确有其事」
- [ ] 有派活原文要点 + 结果事实，不是纯感想
- [ ] 无教程腔、无神话、无增长房口径、无卖课
- [ ] 引用外部帖/人/工具均有可点开链接
- [ ] 未代写他人经历；转述已标来源
- [ ] OpenClaw / Hermes / Workbuddy 若出现，只作对照一句，不抢主线

## 不收（投稿前自筛）

空感想；「万能用法」清单；无法核验的匿名传说；删文件类操作未获 Mai 确认的叙述当作推荐做法。

## 极简示例结构（勿照抄内容）
